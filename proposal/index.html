아이디어 주제공공 의료데이터 기반 대화형 병원 안내 챗봇 서비스
리버스
엔지니어링
챌린지 포인트		기존 굿닥의 ‘조건별 필터 검색’을 분해하여, 사용자가 조건을 직접 고르지 않고 자연어 한 문장으로 말하면 시스템이 조건을 추출·조합해 병원을 찾아주는 구조로 재구성
- 분해 대상 : 지역 선택 → 진료과 선택 → 시간 필터 → 목록 확인의 4단계
- 재구성 결과 : 문장 1개 입력 → 조건 4개 동시 적용 → 근거와 함께 3곳 제시
제안 배경
및 필요성		▪ 시장현황 및 필요성
- 시장 분석 : 전국 요양기관 79,819곳(17개 시도, 256개 시군구)을 심평원 Open API로 직접 수집하여 규모를 확인함
- 문제점 발견 : 굿닥 앱 리뷰 4,311건(2017-05~2026-08) 중 부정 리뷰 837건(19.4%)을 분석한 결과, ‘원하는 조건의 병원을 찾지 못한다’는 불만이 반복 확인됨
- 문제점 개선 : 사용자가 조건을 직접 조합하지 않고, 말한 문장에서 시스템이 조건을 추출해 검색하도록 개선
- 서비스 필요성 : 잘못된 병원 선택은 재방문·교통비·시간 손실로 이어짐. 실제 리뷰에 ‘병원비보다 교통비가 더 나가겠다’는 지적이 있음
- 차별점 : 모든 추천에 이유를 함께 제시하고, 확보하지 못한 정보는 ‘미확인’으로 명시함
- 출처 : 공공데이터포털 건강보험심사평가원 Open API, Google Play 굿닥 앱 리뷰
유사 제품 현황
및 비교		▪ 기존 서비스 및 유사 제품 분석 및 비교


▪ 차별성 기입
- 조건을 고르는 것이 아니라 말하면 됨. ‘비염인데 일요일에 하고 주차되는 가까운 병원’ 한 문장으로 4개 조건이 동시에 적용됨
- 모든 추천에 이유를 붙임 (예 : 0.42km, 이비인후과 진료, 전문의 2명, 주차 20대, 평가 2.5등급)
- 없는 정보를 지어내지 않음. 이용자 별점은 공공데이터에 없으므로 안내하지 않고 정부 적정성 평가등급으로 대체함
- 지역이 모호하면 되물음. ‘북구’는 부산·대구·광주·울산에 모두 존재함
제안 내용▪ 개발 목표
공공 의료데이터를 활용한 대화형 병원 안내 서비스를 굿닥 홈페이지에 제공함으로써, 어느 병원에 가야 할지 판단하기 어려운 이용자의 탐색 부담을 줄이고 적절한 진료과와 병원으로 연결
▪ 개발 내용
- 자연어 조건 추출 기능 : 문장에서 14개 항목(진료과·지역·시간·주차·전문의 등) 추출
- 증상 → 진료과 변환 기능 : 질병명을 생성하지 않고 진료과 힌트로만 변환
- 전국 지역 인식 기능 : 256개 시군구 인식, 동명 지역은 재확인
- 조건 검색 기능 : 진료과·지역·종별·전문의 수·거리 필터
- 시간 조건 검색 기능 : 지금 진료중 / 일요일 / 토요일 / 야간응급 / 특정 시각까지
- 주차 조건 검색 기능 : 주차 가능 대수 기준 필터
- 설명 가능한 추천 기능 : 추천 이유를 항상 함께 출력
- 예약 안내 기능 : 병원 → 진료과 → 날짜 → 시간 → 확인, 전화 연결 및 예약 페이지 이동
- 의료 표현 차단 기능 : 진단 유도 문장에 병명 미출력 (단위 테스트로 검증)
- 챗봇 위젯 화면 : 홈페이지 우측 하단 도우미, 모바일 대응

기대효과
및 활용방안		▪ 기대방향
- 병원 선택에 드는 탐색 시간 단축 : 조건 4개를 동시에 적용하는 검색이 1~2회 대화로 종료
- 헛걸음 감소 : 진료시간·휴진일을 공공데이터로 확인하여 ‘갔는데 문 닫았다’는 불만 감소
- 정보 탐색 취약층 포용 : 조건 필터를 다룰 줄 몰라도 말로 찾을 수 있음
- 이탈 방지 : ‘네이버 검색이 더 편리하다’는 리뷰가 실제로 존재함
▪ 활용방안
- 약국 찾기로 확장 : 심평원 데이터에 약국 정보가 포함되어 동일 구조로 확장 가능
- 비급여 진료비 비교 : 이미 활용신청을 완료한 API로 구현 가능
- 지자체·보건소 안내 서비스로 이식 : 공공데이터 기반이므로 공공 영역 이식이 쉬움
- 고령자 대상 음성 인터페이스 : 조건 추출 로직은 그대로 두고 입력 방식만 교체

(1) 제안 배경 - 외부 환경 분석 (PEST / STEEP)

기술적 배경▪ 기술적 배경
- 기술 혁신 : 공공데이터포털을 통해 건강보험심사평가원의 병원 정보가 Open API로 개방되어, 전국 요양기관의 위치·진료과·진료시간·주차·평가등급을 조회할 수 있음
- R&D 활동 : 본 프로젝트는 4종 API(병원정보 / 의료기관별상세정보 / 병원평가정보 / 비급여진료비)의 활용신청을 완료하고 실제 호출로 응답을 확인함
- 자동화 : LLM과 LangChain의 보급으로 자연어에서 조건을 구조화하는 기능을 소규모 팀도 구현할 수 있는 환경이 됨
- 진입장벽 : 의료 분야는 오작동 시 위험이 크므로, LLM이 응답하지 못할 때를 대비한 규칙 기반 대체 경로를 함께 구현하여 안정성을 확보함
- 아웃소싱과 기술투자 : 공공 API가 무료로 개방되어 별도 데이터 구매 없이 전국 단위 서비스가 가능함
사회·경제적 배경▪ 사회적 배경
: 인구·가구 변화 — 1인 가구와 맞벌이 증가로 평일 낮 병원 방문이 어려운 인구가 늘어, 야간·주말 진료 가능 여부가 병원 선택의 핵심 조건이 됨
: 연령대 분포 — 고령화로 의료 이용은 늘지만, 정보 탐색에 익숙하지 않은 층은 여러 조건을 직접 필터링하는 방식에 어려움을 겪음
: 가치관 변화 — 코로나19 이후 비대면 진료와 앱 접수가 일상화되어 앱에서 병원 정보를 확인하는 행동이 자리 잡음
▪ 경제적 배경
: 의료비 부담 — 비급여 진료비를 사전에 비교하려는 수요가 있으며 심평원이 해당 정보를 공개하고 있음
: 기회비용 — 잘못된 병원 선택은 재방문·교통비·시간 손실이라는 직접 비용이 됨
: 운영 원가 — 공공데이터는 무료로 제공되어 서비스 운영 원가가 낮음
: 규제 환경 — 의료법상 비의료인의 진단 행위는 금지되므로, 진단을 하지 않고 ‘어느 진료과로 가면 되는지’만 안내하도록 설계 단계에서 제약을 둠

국내시장 규모

(3) STP 전략

시장 세분화
Segmentation		▪ 서비스가 배포될 시장을 정의하고 소비자 층을 세분화
- 시장 구분 : B2C (일반 소비자 대상). 기존 플랫폼 안에 기능을 얹는 형태이므로 B2B2C 성격도 함께 가짐
- 상황 : 갑작스러운 증상 발생 / 만성 질환 정기 방문 / 자녀 동반 진료 / 야간·주말 발생
- 연령대 : 20~30대(정보 탐색 능숙) / 40~50대(가족 단위 의사결정) / 60대 이상(탐색에 어려움)
- 거주지 : 수도권(선택지 과다로 비교 피로) / 지방(선택지 부족, 이동 거리 부담)
- 라이프스타일 : 평일 낮 방문 가능 / 평일 낮 방문 불가(직장인·학생)
- 정보 활용 수준 : 조건 필터를 직접 다루는 층 / 검색 자체가 부담인 층
표적 시장
Targeting		▪ 시장 세분화를 통해 구분된 소비자 층에서 이 서비스를 선택할 가능성이 높은 핵심 소비자층을 선별
- 핵심 표적 : 갑작스러운 증상이 생겼으나 어느 진료과·어느 병원에 가야 할지 판단하기 어렵고, 시간 제약(야간·주말·퇴근 후)이 있는 20~40대 생활인
- 선정 근거 1 : 부정 리뷰 분석에서 ‘병원 탐색·선택 실패’가 AI로 해결 가능한 영역 중 가장 큰 비중을 차지함
- 선정 근거 2 : 조건이 복잡할수록(시간·거리·진료과 동시 고려) 기존 필터 검색의 불편이 커지므로 대화형 안내의 효용이 가장 큼
- 선정 근거 3 : 해당 층은 앱 사용에 익숙해 채팅 인터페이스 진입 장벽이 낮음
포지셔닝
Positioning		▪ 표적 시장의 고객이 서비스를 이용할 수 있도록 유도하기 위한 아이덴티티나 이미지
- 아이덴티티 : “진단하지 않는다. 병원 선택만 돕는다.”
- 기존 병원 검색 서비스 : 정보를 나열함 — 판단은 사용자의 몫
- 증상 검색 서비스 : 질병을 추정함 — 의료법·신뢰성 문제
- 본 서비스 : 판단하지 않고 ‘어디로 가면 되는지’를 근거와 함께 안내함
- 신뢰 이미지 : 모든 추천에 이유를 제시하고, 확보하지 못한 정보는 없다고 명시함. 지어내지 않는 태도 자체를 서비스의 이미지로 삼음
